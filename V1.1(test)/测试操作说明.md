# 测试工程案例

独立复制自 sofeware_V2（2026-10-30），原工程未修改。保留 STM32、CC1310 收发端、厂商驱动、构建脚本和原上位机功能；历史 build、抓图和测量结果不复制，防止旧结果混入新实验。

## 启动

1. 在本目录执行 `./build.ps1 all`，默认 APP=stream、TRANSPORT=dual、480X360；生成 build/STM32U575_stream.elf、.bin、.hex。
2. STM32 测试固件需要烧录后按钮才能改变真实状态；当前使用CMSIS-DAP，对应原始目标是`./build.ps1 flash-dap`。2026-11-02已通过指定DAP序列号烧录并校验新版STM32测试固件。
3. CC1310：`./cc1310/build.ps1 APP=rf_image_tx BAND=433 BUILD_DIR=build_test_tx all`，接收端将 APP 改为 rf_image_rx、BUILD_DIR 改为 build_test_rx。发送端增加 ACK 失败/重传统计，接收端新增命令下行和状态混流协议，两端必须配套更新。烧录脚本 `rf_validation/flash_image_board.py` 的使用和芯片身份核对见 RF_IMAGE_LINK.md。
4. `python tools/stream_server.py --source rf433 --rf-port COM20 --rf-baud 921600 --http-port 8081`。安装依赖可用 `python -m pip install -r requirements.txt`。
5. 浏览器访问 http://localhost:8081 。首页为8项实验。电脑仅需连接接收端 COM20；COM30、COM34 均不由上位机打开。命令由接收端通过433 MHz转发到发送端，再经SPI交给STM32；板端状态和发送日志沿同一路径回传。COM33和COM19是辅助端口。

## 各项测试

|编号|操作与实际状态|
|---|---|
|①|整套发送端先断电；点击①待命；在实际合电时点“标记实际上电时刻”。固件冷启动固定480×360/JPEG QS12，采集发送一张后等待。上位机只在收到校验通过且解码成功的480×360 JPEG无线帧后记成功。真实断电重复5次，JSON保留5次时间。按钮时刻含人工误差，不能当精密仪表测量；若首帧漏收则本次失败，应断电重做，不能用软件重启代替。|
|②|照明关闭，摄像头0x3008软待机且XCLK关闭，电源轨保持开启；STM32 Sleep，SysTick仍工作；TX MCU轮询SPI并约100ms发起一次无线控制轮询、RF核保持供电；RX若仍通电则继续等待无线。不是Stop/深度睡眠，也不是整机最低功耗。|
|③|摄像头和STM32连续JPEG采集，不发送SPI图像或图像镜像；SPI仍交换无线控制和状态，采集计数日志限1秒一次。|
|④|固定480×360、QS12、500kbps、433.92MHz、射频功率寄存器0x913F，LED关；顺序采集/发送，关闭并行流水线及图像镜像。寄存器值沿用已验证的433MHz配置，不把寄存器值当成实测dBm。|
|⑤|与④完全相同，PG14四灯共用，低电平有效；仅改50Hz软件PWM占空比，5%一档。测量记录必须保留占空比；不支持四灯分别控制。|
|⑥|点击⑥后手动关闭接收机实际供电（仅关闭网页或串口不会停止RF ACK）。TX每分片最多3次尝试，ACK等待65ms；失败丢弃本帧无线后续片段但继续排空SPI。先等待⑥无线确认，再关闭接收端供电；关闭期间电脑无法收到日志或下发停止命令。发送端有限缓冲日志，恢复接收端供电后补报；缓存满会丢弃部分阶段日志。用仪表保存关机期间发送端能量，恢复接收端后查询状态并停止。|
|⑦|设周期，默认10秒，启动到启动计时；每次唤醒摄像头、采一张、发送一张，再软待机等待。周期超时跳过错过的时隙，不突发补拍。cycle_start和cycle_wait提供阶段标记；完整周期能量需覆盖下一周期开始前的等待，保留日志开销。|
|⑧|两次独立运行：选择“等待接收”暂停发送，RX继续轮询接收；选择“持续接收”启动④相同图传。仪表接RX供电通道，分别导入rx通道采样。RX的接收窗口为15ms并反复重启，UART下行使用中断环形缓冲，等待态仍持续工作。|

测试切换前按“停止”。页面先显示等待确认，收到匹配请求编号及参数的 `[TEST] event=status proto=3 transport=rf433` 后才显示运行中/已停止。10秒未确认则提示状态未确认，不能视为成功；无线链路不可达时停止不会误报成功。停止命令需等当前SPI发送/超时返回才能处理，不能立刻打断一个分片。若未取得15秒内的无线板端状态，①允许先待命，其余测试报错。网页保留最后一张图，用图像年龄判断是否有新帧。

图像协议成功、SPI发送成功、RF ACK成功分别记录；spi_ok不等于无线到达。各测试包含SPI控制轮询、无线控制/状态和保留SysTick的固定开销；②③不能作为完全射频静默的功耗基线。相机软待机寄存器与恢复效果仍需实板确认，不能据此声称完成硬件功耗验证。

## 测量与导出

界面导入CSV：`t_s,voltage_v,current_a`（秒、伏、安）。通道可选system/camera/mcu/tx/rx，同通道再次导入替换原值。采用梯形积分 ∫U(t)I(t)dt，得到J；至少两点才有有效积分区间。时间应与测试开始对齐，记录仪表触发偏差。系统输入与内部电源轨不要相加，避免重复计能量。没有仪表采样时energy_j为空，不生成模拟功耗。

每次实验自动写入 test_results/<时间_标识>.json。结束后导入仪表采样再下载完整JSON；支持保存测试条件、阶段日志、有效帧、起止统计和5次上电组。运行中事件保留最近10000条，截断标记events_truncated；需要长测完整波形请保存仪表原始文件。服务重启会恢复最近记录和上电组，原运行中的会话标记中断，需要重新启动，不会自动改变板端状态。状态查询每5秒经433 MHz发一次H0并产生无线状态回报，测量包含这部分固定开销。采样至少2点。

## 接口

* `POST /test/action` JSON：`{"action":"start","case":4,"duty":50,"interval":10,"phase":"wait","note":"备注"}`。
* action还支持query（H0查询状态）、stop、power_on、reset_boots、samples。
* 仪表接口：`{"action":"samples","channel":"tx","samples":[{"t_s":0,"voltage_v":3.3,"current_a":0.02},{"t_s":10,"voltage_v":3.3,"current_a":0.03}]}`。
* `GET /test/state` 获取状态；`GET /test/export` 下载完整JSON；原有/stats、/logs、/stream保留。
* STM32命令：H0查询，A1..A999999设置请求编号，E0停止，E1..E8选择测试；I1..I3600周期秒；E5后L0..L100设置照明占空比。按A/I/E/L/H顺序发送，板端status返回rid、case、led、interval_ms、standby、captures、sends。E8暂停发送，⑧持续接收阶段由上位机映射E4。旧画质/分辨率/帧率命令在测试固件中忽略以锁定对照条件。

## 当前硬件检测

实际无线链路的检查结果见 ../V1.0/validation/basic_link_2026-11-01.json。这份2026-11-01基本链路记录对应当时的原图传固件；2026-11-02已切换新版测试固件，部分功能响应记录见validation/hardware_ready_check.json。测试页面仍会拒绝在已识别的原图传固件上启动实验。启动脚本默认串口已更新为本次接线。

无线协议：电脑到接收板使用 WRC1 + uint16长度 + ASCII批命令 + FNV-1a校验；状态上行使用 WTS1 同结构。无线WC包携带协议版本、类型、会话和序号；命令需STM32取到后才出队，重复批命令去重，板端rid状态另行确认实际执行。接收板未送达的命令8秒过期；超时后仍应查询实际状态，不把本机写入或RF应答当作执行成功。TX最多暂存15条状态消息，接收板最多排队7批命令。
