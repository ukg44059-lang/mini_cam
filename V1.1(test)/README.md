# V1.1(test)：四档整机电流测试

当前保存点：`v1.1-test.3`，2026-11-02（America/Denver）。从此前八项实验改为用电表在发送端整机输入处进行逐档对比。V1.0和此前测试版标签保留，可按根目录README回溯。

|模式|摄像头|STM32|433 MHz|
|---|---|---|---|
|① 完整运行|480×360 JPEG QS12，目标每秒采集一张|保持运行、采集和SPI转发|图像发送＋双向控制|
|② 不发无线图像|与①相同采集条件和节奏|保持运行和采集，不做SPI图像转发|双向控制，停止图像发送|
|③ 摄像头待机|软待机、关闭XCLK，供电未切断|保持运行，继续控制轮询|双向控制|
|④ STM32 Sleep|与③相同|轮询之间WFI，保留1ms时基|双向控制|

四档LED始终关闭。无线芯片不进入休眠，命令、功能标志、模式执行确认和日志继续通过433 MHz往返；电脑仅打开接收端CC1310应用口。STM32与发送端CC1310之间沿用板内SPI，发送端独立供电。

①②都按固定1秒采集槽运行，处理过慢时跳过周期并报告skipped，不补发一串图像。出现采集失败、跳过周期或无线帧校验/完整性错误时，读数保留并标记不适合差值对比。

## 怎么用

在仓库根目录运行：

```powershell
./Build-Version.ps1 -Version 'V1.1(test)'
& './V1.1(test)/启动测试上位机.ps1' -ReceiverPort COM42
```

网页为 http://localhost:8081/ ，图像和接收口设置在 `/viewer`。当前电脑实测接收端应用口为COM42、921600，COM41是辅助口；Windows重新枚举后端口号可能变化。构建不自动烧录。最新STM32固件必须是`proto=4`；八项版`proto=3`无法驱动四档页面。CC1310收发固件沿用`v1.1-test.2`的双向无线控制版本。

按①→②→③→④选择，每次等待匹配请求编号及模块状态的无线确认，再稳定5秒、观察电表30秒（可选5～600秒）。完成观察后保持当前档，输入电表的电压V和整机电流mA，点击“记录本档”。可导出JSON，点击①或“恢复完整运行”恢复图传。测量前接好独立电源；下载完成后可断开DAP，减小调试连接对电流测量的影响。

软件不采集电表数值，不把倒计时当作能量积分。输入功率mW=电压V×电流mA。相邻档差值属于整机模式差异：②相对①包含SPI、无线图像和相应CPU工作变化；③相对②包含摄像头采集、ISP/JPEG、DMA和CPU处理变化；④相对③反映MCU运行/Sleep模式差异。不能据此分离JPEG、ISP、MCU绝对功耗或LDO损耗。

## 本次验证

- STM32与两端CC1310构建通过；本次只更新并烧录STM32，OpenOCD `Verified OK`。收发端无线协议未修改，仍为此前已烧录版本。
- [实板记录](validation/four_mode_hardware_check.json)：11段模式/恢复检查；①的4.5秒观察窗口均收到4张有效图像，②采集4～5张但不发无线图像，③④采集计数不变；新增CRC错误、不完整帧和跳过周期均为0；暂停确认及恢复①成功。
- [网页检查](validation/browser_validation.json)：真实页面按钮切换Sleep和恢复完整运行、倒计时门控、桌面与390px宽度、无脚本异常；未输入任何电表数值。
- [离线回归](validation/offline_validation.json)：模式映射、请求/协议/状态匹配、超时、旧回执、断线、读数计算、异常值、导出与重启恢复。计算测试数据仅存在临时目录。
- 延长运行观察到采集719ms＋发送359ms超过1秒采集槽，固件跳过周期，上位机标记本档不适合差值对比。请重新选档开始新的读数记录；短窗口验证的0跳周期不代表长时间绝无跨槽。
- 6项无线混流/损坏恢复检查和C无线协议边界检查通过。电流、电气时钟/休眠程度、JPEG/ISP分项和LDO损耗尚未实测。

操作步骤、模式差值含义及HTTP接口见[测试操作说明](测试操作说明.md)。之前八项实验的历史记录对应旧标签，不表示本次四档功耗已经完成测量。
