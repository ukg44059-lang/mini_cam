# V1.1(test)：功耗与状态测试工程

基于 V1.0 基本图传增加测试控制，导入来源为本地 `测试工程案例`。本版本是实验代码保存点：固件编译、上位机离线接口和协议检查通过，8项实际硬件实验尚未完成；不能标记为已验证稳定版本。

2026-11-02 更新（`v1.1-test.1`）：增加带请求编号的板端确认、查询接口、确认超时提示和服务重启记录恢复。STM32 与发送端CC1310已烧录并校验；接收端继续使用已工作的原接收固件。②/③/④/⑤命令/⑦/⑧两阶段的功能响应已检查，尚未完成①真实断电5次、⑥接收机关机和仪表功耗实测。当前可以开始这些人工实验。

2026-11-02 更新（`v1.1-test.2`）双向无线控制：电脑只连接接收端CC1310，测试命令和发送端状态通过433 MHz往返，STM32不再通过COM30控制，TX也不需要COM34日志线。三端固件已烧录校验，②③④⑤⑦⑧的无线功能响应通过，详见validation/wireless_hardware_check.json；①物理断电5次、⑥物理接收机断电及功耗仍需实测。

## 增加了什么

|测试|实现|
|---|---|
|① 上电初始化|真实断电后标记上电，记录首张有效无线图像，重复5次；人工时刻有误差|
|② 系统等待|LED关、摄像头软待机并关XCLK，MCU Sleep保留SysTick及低频控制轮询，记录各模块状态|
|③ 只采集图像|摄像头＋STM32采集，不发图像；保留无线控制/状态|
|④ 连续无线图传|固定480×360、QS12、500kbps和功率寄存器0x913F，顺序采集发送，LED关|
|⑤ 加照明|与④同参数，只改50Hz软件PWM照明占空比|
|⑥ 接收机关闭|接收机实际断电后观察TX等待ACK、重试和超时；状态会在接收端恢复后经无线补报|
|⑦ 间歇拍照|默认每10秒采一张并发送，间隔软待机；记录周期阶段|
|⑧ 接收端持续工作|分别设置等待接收和连续收图阶段，外部测量RX功耗|

网页提供8项按钮、占空比和周期设置、状态日志、JSON导出；仪表CSV导入按U×I积分得到能量。软件未读取电流传感器，未导入仪表数据就没有功耗实测值。测试参数固定，原图传界面的画质命令在测试固件中被忽略。

## 验证到哪一步

- `v1.1-test.1` 中STM32、CC1310 TX/RX均已重新构建；此前烧录过的STM32和TX已校验，RX使用兼容图像固件。`v1.1-test.2`已构建、烧录并校验三端固件。
- 离线测试：8项入口、命令映射、5次上电记录门控、采样积分/非法值拒绝、导出/落盘和协议恢复。见 validation/offline_validation.json 和 validation/receiver_validation.txt。
- 功能响应记录见 validation/hardware_ready_check.json 与 post_tx_update.json：仅采集不产生无线帧、等待和停止进入软待机、连续及间歇模式产生图像，照明20%命令确认。未进行LED电气占空比、物理断电、无接收机重试或周期能量测量。
- 无线功能检查全程独占COM30和COM34，上位机仍正常无线启停、获取状态和收图；连续6秒11张、间歇6秒3张，校验错误和不完整帧0。⑥仍需物理断电实测。
- 等待态为保留1ms时基的Sleep，不是Stop/最小功耗；TX仍轮询SPI并低频轮询433 MHz链路，③不发图像但保留低频控制/状态通信，测量包含这些开销。

上位机能根据 `[PERF]` 和 `[TEST]` 区分已识别的原图传/测试固件；识别为原图传固件时拒绝启动测试，避免把串口写入成功当作板端切换成功。固件状态未知时仍须核对实际 `[TEST] event=case`。

## 使用

在仓库根目录：

```powershell
python -m pip install -r 'V1.1(test)/requirements.txt'
./Build-Version.ps1 -Version 'V1.1(test)'
& './V1.1(test)/启动测试上位机.ps1'
```

打开 http://localhost:8081/ 。上位机仅打开接收端CC1310应用口，默认COM20、921600；COM19是辅助口。无需连接STM32 DAP串口COM30或发送端状态口COM34。先烧录本版本三端测试固件，再在页面查询状态，确认15秒内收到 `proto=3 transport=rf433` 后运行实验；构建脚本不自动烧录。

具体接口、采样单位和测试步骤见 [测试操作说明](测试操作说明.md)。`Core/Src/app_stream.c` 是STM32测试状态控制，`tools/test_console.py` / `test_console.html` 是上位机接口和按钮，`cc1310/Core/Src/app_rf_image_tx.c` 和 `app_rf_image_rx.c` 复用433 MHz链路承载控制及状态。

标签为 `v1.1-test`，验证状态为“待硬件验证”。若测试版改坏或运行不稳，先恢复 `v1.0` 基本图传；不要复用本标签覆盖未来修复。导入来源见 SOURCE_ORIGIN.json，完整归档校验见 SNAPSHOT.json。

上述`v1.1-test`是最初保存点；当前更新标签为`v1.1-test.2`，上一保存点为`v1.1-test.1`。已发布旧标签均保留。
